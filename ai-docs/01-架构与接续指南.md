## 1. 工程结构

```
idle-dark-forever/
├── packages/
│   ├── protocol/           # 共享线协议（唯一真相）：cmd 段 + DTO + 结果约定 + 业务错误码
│   ├── game-core/          # 纯 TS 游戏内核（无 MobX / 无 IO）
│   │   └── src/
│   │       ├── contracts/  # ★ 冻结契约：ports.ts（Clock/Rng/BattleSink）、data.ts（数据表类型）
│   │       ├── rng/        # 可重放 PRNG
│   │       ├── sim/        # 虚拟时钟：PrivQueue + Timeline（移植自原版）
│   │       ├── data/       # 183 个数据文件的 TS 化（显式组装，无模块级副作用）
│   │       ├── rules/      # 持久化模型与规则：InventorySlot / Player / goods / check
│   │       └── serialize/  # 存档编解码（导入旧本地存档）
│   ├── server/             # NestJS + ionet-ts 权威服务端
│   │   └── src/
│   │       ├── main.ts     # ★ 启动顺序不可换
│   │       ├── app.module.ts
│   │       ├── ionet/      # 框架适配：app-ref / cmd / action-support / game-actions / route-check
│   │       ├── common/     # auth / guards / decorators / ports(NotificationPort) / kernel / services
│   │       └── modules/    # database / auth / character / health / edge / online / logic/*
│   ├── ionet-transport/    # 前端传输层（消费 @nbb-ionet/client-protocol）
│   ├── ui-kit/             # 纯 antd 组件层（零业务）
│   └── web/                # React + Vite + Antd + MobX 业务前端
├── vendor/ionet-ts/        # 框架源码（CI 挂载 / 本地符号链接，**不提交**）
└── ai-docs/
```

## 2. 依赖方向（硬约束）

```
web → ionet-transport → protocol
web → ui-kit              （ui-kit 只允许 import type @idle-dark/protocol 的类型）
server → game-core → protocol
server → protocol
```

- `game-core` **不得** import MobX / React / DOM；**不得**裸用 `Math.random()` / `Date.now()`。
- `ui-kit` **不得** import 任何业务包 / store / 传输层（有门禁测试强制）。
- `web` **不得** import 除 `@nbb-ionet/client-protocol` 之外的任何 `@nbb-ionet/*`（其余包依赖 Node `async_hooks`，浏览器加载即炸）。

## 3. 并行开发的关键约定

### 3.1 冻结契约
`packages/game-core/src/contracts/{ports,data}.ts` 与 `packages/protocol/src/**` 是**冻结契约**：
并行开发期间禁止改形状；需要扩展时**只加可选字段**，或新增契约文件。

### 3.2 端口注入（不使用 MobX 的代价与对策）
原版靠 MobX 的 `reaction` / `autorun` 实现「到点自动施法」「攻速改变时间倍率」。
移植后改为**显式调度**：随机走 `Rng` 端口、时间走 `Clock` 端口、战斗事件走 `BattleSink` 端口。
这样同一套内核可以在三种环境跑：服务端在线模拟、离线有界快进、单测确定性重放。

### 3.3 随机数与确定性
原版全仓库直接 `Math.random()`（掉落品质、词缀、暴击、刷怪位置、炼金）。移植后一律经 `Rng`。
**同一 `(种子, fork 标签)` 必然产生同一序列**——这是离线结算可审计、单测可稳定、数值回归可对比的前提。

## 4. 线协议要点（详见 ionet-ts `PROTOCOL.md`）

| 项 | 值 |
|---|---|
| 请求 | `{ cmd, subCmd, data?, headers?, traceId?, reqId? }` |
| 响应 | `{ data?, errorCode?, errorMessage?, reqId?, kind? }`（不回显 cmd/subCmd） |
| 推送 | `{ kind:'notification', type?, cmd?, subCmd?, data?, timestamp? }` |
| 错误码 | `0/undefined` 成功、`400` 解析失败、`404` 路由不存在、`500` 内部异常 |
| 鉴权 | WS 握手期 `authenticate` → `{userId: bigint}`；浏览器用 `?token=<jwt>` |
| 心跳 | WS 协议层 ping 浏览器不可见 → 客户端用应用层 `system.ping`（15s） |

### 4.1 两级错误判定（硬契约）
1. 响应 `errorCode !== 0` → **传输错误**
2. `errorCode === 0` 但 `data.success === false` → **业务错误**（码在 `data.data.code`）
3. 其余 → 成功

> ⚠️ 只判 `errorCode` 会把**全部业务失败当成功**。

### 4.2 已知框架规避项
| 框架问题 | 规避方式 |
|---|---|
| HTTP 裸 object DTO 被当信封解包 | 业务 object DTO **一律**用 `{data:{...}}` 包装 |
| `RateLimitInOut` 无法短路（骨架不读 `ctx.errorCode`） | 自建限流，抛错或返回 `fail(RATE_LIMITED)` |
| NestJS 默认直接 `new` Action，不经容器 | `resolveAction: (Cls) => appRef.app!.get(Cls)`，Action 加 `@Injectable()` |
| `NODE_ENV=production` 默认拒启动 | 显式 `allowProduction` |
| `FlowContext` 用 `import type` 会导致鉴权静默失效 | **必须值导入** |

## 6. 接续点（新增一个游戏域要改哪些文件）

1. `packages/protocol/src/cmd.ts` —— 登记段与 subCmd（若已有段则加 subCmd）
2. `packages/protocol/src/dto.ts` —— 该域的请求/响应类型
3. `packages/server/src/modules/logic/<domain>/` —— `*.action.ts`（只校验转发）+ `*.logic.service.ts`（门面编排）+ `internal/`（实现）
4. `packages/server/src/ionet/game-actions.ts` —— 登记 Action 类与 Module
5. `packages/ionet-transport/src/api/game-api.ts` —— 加 typed 方法（**cmd 常量直接来自 protocol，禁止手工镜像**）
6. `packages/web/src/stores/<domain>-store.ts` + `pages/game/panel-registry.tsx` —— 注册面板
7. 单测：规则层放 `game-core`（纯函数易测），编排层放 `server`（用内存端口替身）

## 8. 工程约定

- 提交信息**不得**含 `Co-Authored-By`。
- 改业务代码必须同步补单测并覆盖边界（undefined/null/NaN/负数/0/空数组/超大值/错误路径）。
- 改动后必须通过 `pnpm run build` 与 `pnpm run typecheck`。
- 工作量度量用「规模 / 测试门禁 / 依赖顺序 / 风险」，**不使用时间单位**。
- 前端页面一律包 `ErrorBoundary`；反馈 API 一律 `App.useApp()`。
