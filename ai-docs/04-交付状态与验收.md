启动形态为**单端口三合一**：REST `/api` 与 WS `/ws` 挂在同一 listener。

### 3.2 游戏内核的可重放性（这是离线结算与反作弊的前提）
- 全包**无裸 `Math.random()` / 裸 `Date.now()`**（唯一真随机入口是 `SeededRngFactory.nextSeed()`，且有显式注释说明理由）。
- 数据层的 52 处随机（技能/Buff/强化/传奇 hook）已改为经 `world.rng.skill` 通道，**全部可重放**；
  并加了「遍历 >600 个数据表函数断言无一含 `Math.random`」的源码扫描护栏防回归。
- 战斗模拟有**金样回归**：固定种子下事件流与状态逐字节稳定（哈希钉死），且「分片推进 == 一次性推进」。
- 存档编解码为**纯 TS 实现**（MD5/SHA-256/HMAC/base64/UTF-8），用 RFC 与 `node:crypto` oracle 双重校验，
  并对整段存档**逐字节篡改测试**（改正文 / 摘要 / secret 任一字节都必须抛错）。

### 3.3 旧存档迁移链路（本工程最有价值的产品功能）
`worldStart` / `worldStop` / `decodeGameSave` / `detectSaveKind` 已就绪，支持三种旧存档形态：
明文 JSON、`'save'+base64` 可逆混淆、HS256 JWT（旧密钥 `chapter5.woodElf`）。

### 3.4 反重放与推送风暴防线
- `OpIdempotencyService`：消耗类操作 `opId` 去重（并发双击挡住 / 成功后回放结果 / 失败必须 `abort` / 非法 `opId` fail-closed）。
- `NotificationBatcher`：按 `(userId, cmdMerge)` 合并 + 定时 flush；超限**真正丢弃**并通过 `meta.resync` 上报，
  让客户端知道快照已陈旧（而不是继续在旧快照上演算）。

## 5. 环境与数据库（必须知道）

沙箱内**没有 PostgreSQL 服务端二进制**（只有 `psql` 客户端）、**Docker daemon 也不可用**，
所以无法在沙箱内自建集群。**但**本机有一台可直接使用的外部 PostgreSQL 实例
（`idle-path-of-xiuxian` 用的那台，凭据在 `packages/server/.env`），因此**数据库端到端验收在本地就能跑**：

| 验收 | 结果 |
|---|---|
| `pnpm run build` / `typecheck` / 测试（950 用例） | ✅ |
| `db:init`（建表，幂等） | ✅ |
| `prisma:validate` / `prisma:generate` / `prisma:pull` | ✅ |
| 服务端启动 + 线协议冒烟 | ✅ **15/15** |
| 路由探针（20 个域 Action 是否都注册） | ✅ **20/20** |
| **完整游戏流程冒烟**（注册→登录→选角→进图→`world.tick` 推送→背包→存档导出/导入往返→幂等→两级错误判定） | ✅ **22/22** |

### 5.1 库的选择：独立数据库 `idle_dark`

`idle_game` 是 xiuxian 的库，其中已有它的 `users` / `characters`（`characters.id` 是 `integer`、
有 `nickname`/`gender`…）与 30 张 `game_*` 表。本工程的 `characters` 列定义完全不同
（`id text` / `name` / `role` / `career` / `state jsonb`）——建在同库会被
`CREATE TABLE IF NOT EXISTS` **静默跳过**，随后查询必然失败。

因此本工程用**独立数据库 `idle_dark`**（同一实例），**不动 xiuxian 的任何表**。

### 5.2 Prisma 的用法（与 xiuxian 一致）

`prisma/schema.prisma` 是**数据设计的唯一真相**；实际 DDL 由 `scripts/init-db.mjs` 执行；
**运行期用原生 `pg`，`src/` 内不 import `@prisma/client`**；`prisma` / `@prisma/client` 只在 devDependencies。

已做**一致性核对**：`prisma db pull` 从线上库反推的 schema 与本仓手写 schema
**零语义差异**（仅字段顺序、对齐空白，以及本仓显式写出的 `@db.Text`/`@db.JsonB`
—— 这两个恰是 PostgreSQL 上 `String`/`Json` 的默认映射）。

### 5.3 CI

`.github/workflows/ci.yml` 声明了 `services: postgres`（库名 `idle_dark`），
构建后依次执行：`prisma:validate` → `db:init` → 线协议冒烟 → 路由探针 → 完整游戏流程冒烟。

> ⚠️ 端口 3000 上可能是 **xiuxian 自己的服务端**（其健康检查响应没有 `service` 字段且会报 `redis`）。
> 本地验证时先确认端口归属，或直接用独立端口。
