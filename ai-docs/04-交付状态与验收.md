## 3. 已完成的关键目标

### 3.1 线协议一致性（真实服务端上验证）
`packages/server/scripts/ws-protocol-smoke.mjs` —— **15/15 通过**，覆盖：

| 条款 | 断言 |
|---|---|
| §6 | 无 token 的握手被 401 拒绝；错签名 token 同样被拒；`?token=<jwt>` 升级成功 |
| §4.1 | reqId 精确配对（响应回显 `reqId` + `kind='response'`）；并发在途各自配对 |
| §4 | 响应不回显 `cmd`/`subCmd` |
| §8 | 未注册 Action → 404；坏帧 → 400；成功响应 `errorCode` 缺失或 0 |
| §12.1 | 旧协议（不带 reqId）响应**不注入** `reqId`/`kind` |
| 工程约定 | `system.ping/version` 遵循 `ActionResult<T>`；时钟对齐字段固定为 `serverTime` |
| 两级判定 | 业务失败 = `errorCode=0` + `data.success=false` + `data.data.code` |

启动形态为**单端口三合一**：REST `/api` 与 WS `/ws` 挂在同一 listener。

### 3.2 游戏内核的可重放性（这是离线结算与反作弊的前提）
- 全包**无裸 `Math.random()` / 裸 `Date.now()`**（唯一真随机入口是 `SeededRngFactory.nextSeed()`，且有显式注释说明理由）。
- 数据层的 52 处随机（技能/Buff/强化/传奇 hook）已改为经 `world.rng.skill` 通道，**全部可重放**；
  并加了「遍历 >600 个数据表函数断言无一含 `Math.random`」的源码扫描护栏防回归。
- 战斗模拟有**金样回归**：固定种子下事件流与状态逐字节稳定（哈希钉死），且「分片推进 == 一次性推进」。
- 存档编解码为**纯 TS 实现**（MD5/SHA-256/HMAC/base64/UTF-8），用 RFC 与 `node:crypto` oracle 双重校验，
  并对整段存档**逐字节篡改测试**（改正文 / 摘要 / secret 任一字节都必须抛错）。

### 3.3 旧存档迁移链路（本工程最有价值的产品功能）
`worldStart` / `worldStop` / `decodeGameSave` / `detectSaveKind` 已就绪，支持三种旧存档形态：
明文 JSON、`'save'+base64` 可逆混淆、HS256 JWT（旧密钥 `chapter5.woodElf`）。

### 3.4 反重放与推送风暴防线
- `OpIdempotencyService`：消耗类操作 `opId` 去重（并发双击挡住 / 成功后回放结果 / 失败必须 `abort` / 非法 `opId` fail-closed）。
- `NotificationBatcher`：按 `(userId, cmdMerge)` 合并 + 定时 flush；超限**真正丢弃**并通过 `meta.resync` 上报，
  让客户端知道快照已陈旧（而不是继续在旧快照上演算）。

## 5. 环境限制（必须知道）

沙箱内**没有 PostgreSQL 服务端二进制**（只有 `psql` 客户端），**Docker daemon 也不可用**。因此：

- **本地可验**：`build` / `typecheck` / `test`（纯逻辑）/ 服务端启动 + 线协议冒烟 15/15。
  数据库不可达时 `/api/health` 返回 `503 degraded` —— 这是**正确行为**，不影响协议层断言。
- **本地不可验**：`db:init`、角色存档读写、以及任何需要真实表的端到端链路。
- **CI 承担**：`.github/workflows/ci.yml` 已声明 `services: postgres`，构建后执行 `db:init`
  与两个冒烟脚本（线协议 + 完整游戏流程）。
