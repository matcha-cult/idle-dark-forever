## 1. 🔴 最高优先：拾取规则「自动出售/分解」不生效

**症状**：面板里设置「某类装备某品质 → 出售/分解」后，战斗掉落仍走 `minLootLevel` 兜底规则，
面板设置**完全不起作用**。

**根因（已逐行确认，两侧键与值类型都不匹配）**：

- 面板侧编码（`packages/server/src/modules/logic/inventory/internal/loots.ts:29-37`）：
  ```
  player.lootRule: Map<string, number>
     '__enabled__'                  → 1 | 0          （全局开关）
     `c:${class}:${quality}`        → action | action+10（停用则 +10）
  ```
- 战斗侧读取（`packages/game-core/src/combat/battle-world.ts:553-565`）：
  ```ts
  const rule = this.player?.lootRule?.get(clazz);   // ← 按 class 取，取不到（键是 c:class:quality）
  const value = rule && rule[quality];              // ← 而且 rule 是 number，再索引 quality 必然 undefined
  const ret = toNumber(value, 0);
  if (ret) return ret;                              // ← 永远是 0，于是继续走 minLootLevel
  ```

**修法（二选一，推荐 (a)）**：
- **(a) 把编码下沉到 game-core，成为唯一定义**：在 `rules/`（或 `combat/`）定义
  `lootRuleKeyOf` / `LOOT_RULE_ENABLED_KEY` / `decodeLootRule`，`getLootRule` 用
  `c:${class}:${quality}` 取值并按 `>= 10` 判定停用；面板侧改为 import 这套定义（删掉自己那份）。
  理由：编码是**跨域硬约定**，放在两侧各写一份必然再次漂移（这次就是这么坏掉的）。
- (b) 保留面板编码，只改 `battle-world.getLootRule` 去适配它——治标，下次仍会漂。

**验证**：
- 单测：`player.lootRule` 分别设为 `{'c:sword:2': 1}` / `{'c:sword:2': 12}` / `{'__enabled__': 0}`，
  断言 `getLootRule('sword', 2, level)` 返回 1 / 落回兜底 / 全局关时直接拾取。
- 端到端：设规则 → 进图打怪 → 检查 `(inventory, changed)` 推送里该品质装备是被卖掉而非入包。
