## 2.2 ✅ 已修复：一个账号同时存在多个角色会话 → 串号 + 双份推送

**症状**：同账号开两个标签页时，「A 里看到的/被推进的是 B 选的角色」，且 tick 推送成倍增长
（上一个问题里"实测 10 帧/秒"就是这个原因的一部分）。

**根因（三处叠加）**：
1. `player.select` 只 `world.start(新角色)`，**不停旧角色的会话** → 两个角色的世界同时 tick；
2. 框架的定向推送 `sendNotification(userId, …)` 会发给该 userId 的**全部 OPEN 连接**；
3. 「当前角色」`WorldService.activeByUser` 是**按 userId 全局**的，且
   `world/battle/idle` 三个 Action 各自写 `body.key ?? activeCharacterOf(userId)`（fail-open），
   而前端 transport 的 `world.snapshot/leave/skipOffline/idle.report/claim` **压根不带 key**。

**实测复现**（修复前）：`A 选 X、B 选 Y → A 不带 key 的 world.snapshot 解析到 Y；
2 秒内 tick A=9 B=10 且 9 帧的 serverTime 完全相同`。

**修法**（无框架改动）：
1. `PlayerLogicService.select`：`start(新)` 后 `stop(旧)` → 同一账号**只有一个活跃角色会话**；
2. `WorldService.stop()` 在指针仍指向该角色时清理 `activeByUser`（切人顺序是
   `start(新) → stop(旧)`，不能无条件清）；
3. 新增唯一入口 `WorldService.resolveActiveCharacter(userId, rawKey)`：**显式 key 必须等于当前角色**，
   否则 `PLAYER_NOT_FOUND('该角色不是当前选择的角色')`；不给 key 才回退当前角色；
   未选角一律拒绝。`world.action` / `battle.action` / `idle.action` 全部改走它。

⇒ 推送到该账号任何连接的消息**只属于当前角色**（原版就是单存档单玩家）。

**验证**：
- 单测 `server/test/character-switch.test.ts`（6 例）。把"停旧会话"去掉 → **3/6 失败**（已实测）。
- 端到端 `server/scripts/character-scope-smoke.mjs`（真实 REST+WS+DB，同账号两条连接）
  **7/7 通过**：非当前角色的显式 key 被拒、不带 key 回退当前角色、tick 帧里只有当前角色、
  两个连接各 ~5 帧/秒且内容一致。
- 见 `AGENTS.md` **§15**。

**追加修复（用户实测反馈）**：刷新页面后停在选角页仍收到 `(world, tick)`。
根因是「当前角色」在服务端不随新连接失效 + `OnlineSessionService.isOnline` 是账号级判据。
已改为**每次 WS 握手成功即 `await WorldService.resetActiveCharacter(userId)`**
（停会话 + 清注册表 + `batcher.drop` 丢弃那批属于上一段游玩的待发帧，2s 超时保护），
前端在「重连」（曾经 online 过之后再次 online）时重新 `select`。
冒烟扩到 **10/10**：新连接（未 select）收到 **0** 帧、`world.snapshot` 报「尚未选择角色」。

**仍待做（同一类问题的剩余面）**：面板域（inventory / bank / shop / career / produce /
lootrule / story）的 `characterId` 仍是可选 + `PanelCharacterService` 按 userId 存当前角色，

## 2.3 ✅ 已修复：数据层用原版属性名 `unit.timeline` → 运行期 `undefined.pause()`

**症状**（用户实测告警）：`WorldService` 打印

**修法**：
1. `data/buffs.ts` 6 处 `this.unit.timeline` → `this.unit.clock`；
2. `data/packages/year2018.ts` 1 处 `this.timeline.setTimeout` → `this.clock.setTimeout`（legend hook，`this` = Unit）；
3. **收口视图类型** `data/_shapes.ts`：`UnitLike.timeline` → `clock`（与真实 `Unit` 一致）——

> 教训：**数据层视图类型（`_shapes.ts`）必须与真实内核成员名一致**，否则它就是下一处
