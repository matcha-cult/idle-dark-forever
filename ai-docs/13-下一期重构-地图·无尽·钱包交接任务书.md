## 0. 一句话结论与三条不变式

**三件事同时做**：

1. **钱包化**：通货 / 精华 / 将来的「一般等价物」**不占背包格**，独立承载；
   **混沌钥石例外** —— 它可加工（最多前缀+后缀共 4 条词缀），走背包。
2. **地图重做**：全新地图种子；等级段 `0~5 / 5~15 / … / 75~85`（**9 段各 1 图**），
   **85+ 允许多图**；解锁只看等级 + **一次性野外 BOSS**；**剧情整体物理删除**；
   怪物按「普通=地图等级 / 稀有+1 / 守关 BOSS+2」生成，**每 20 波**出 BOSS。
3. **混沌仪 + 混沌钥石**：混沌仪是**无尽挂机专属建筑**，解锁条件 = **通关全部野外地图 BOSS**；
   玩家在混沌仪上**编排钥石顺序 → 逐个挑战**（全自动挂机）；**失败选项** = 回普通地图挂机 / 继续挑战。
   无尽 **T1~T16**，开图 UI **只显示 T 阶**（等级让玩家自己算，地图等级 = `84+T`）；
   混沌钥石 **16 种**，由 **85+ 区域**怪物掉落，**最多掉比自己高 1 阶**的钥石；
   **存量「氪金秘境」体系（票/冷却/队列）直接弃用**。

**三条不变式（违反即返工）**：

- **I1 无存量兼容**（沿用 `12` 的 P1）：新地图 / 钱包 / 钥石上线即**清库重开**
  （`DELETE FROM users;`，级联清 `account_state` 与 `characters`，**绝不动 xiuxian 的 `idle_game`**）。
  不写任何迁移分支。
- **I2 冻结契约只许加可选字段**：本次**必然动** `MapData`（新地图语义）、`PlayerStateDto`（钱包投影）、
  `GoodData`（钱包标记/钥石标记）、`Requirement`（去 `stories`）；**`GoodType` 四个值不动**
  （钱包物品仍用 `type:'material'` + 标记位，避免协议破坏与前端排序回归）。
- **I3 逻辑服边界要重画**：`story` 域物理删除后，`modules/logic/shared/events.ts` 的
  `MapEntered` / `EnemyKilled`（battle→quest）要一并清理或改挂新域；
  `logic-server-boundary.test.ts` 的 SCC/白名单门禁必须同步更新，**不得留悬挂事件**。

## 1. 三条设定逐条解读（现状对照 + 坑）

### R1 钱包：通货 / 精华 / 一般等价物不占背包格

**[设定]**
- `currency.*`（12 种工艺通货）、`essence.*`（6 种精华）、以及**后期新增的「一般等价物」**全部进**钱包**。
- **混沌钥石不进钱包**（见 R3）。

**[现状]**
- 通货/精华现在是 `type:'material'` + `stack:9999` 的普通物品，**占背包格**；
  刚把默认背包从 4 扩到 **50** 格（`DEFAULT_INVENTORY_SIZE`，`player.ts:53`）。
- 落地路径：`BattleWorld.lootGood` → `PlayerLike.loot`（server 的 `toPlayerLike`）→ `Player.loot`。
- 背包 UI：`web/src/pages/game/panels/InventoryPanel.tsx` + `stores/inventory-store.ts`（按 `position` 分组）。
- `lootRule` 域已休眠（装备不再掉落），但协议段 `lootrule:70` 仍在。

**[坑]**
1. **钱包必须绕过 `Player.loot` 的堆叠/空格逻辑**，否则「不占格」是假的。
   建议在 `Player` 上加 `wallet: Map<string, number>`（或 `Record<string, number>`），
   由 `Player.loot` 对「钱包物品」走独立分支（无上限、不进 `inventory`）。
2. **离线报告 / `(battle, loot)` 推送 / 拾取规则**都要认钱包物品：
   `LootDto.slot` 目前是 `InventorySlotDto`，钱包物品没有 `position:'inventory'` 的格子。
   要么给钱包物品发一条带 `wallet:true` 的 DTO，要么复用同一 DTO 但前端按标记分流。
3. **`PlayerStateDto` 要加钱包投影**（`wallet: Array<{key,count,name,...}>`），且**前端零推导**。
4. **已落地的「掉落如实上报」**（`handled:'lost'`、`Player.loot` 返回入包数）必须保留：
   钱包路径永远成功（无容量上限），所以钱包物品不会再出现 `lost`。
5. 交易/出售：钱包物品能否卖店？现有 `opSell` 只作用于背包格子。**待拍板**（§2.4）。

3. **剧情可物理删除**（用户原话："剧情强绑定角色，体验一般"）→ 整个 story/quest 体系退役。

   | 守关 BOSS | 地图等级 **+2** |

5. **守关 BOSS 时机**：**每 20 波**怪物出现一次；**野外 BOSS 只可击杀 1 次**（一次性）。

### R3 混沌仪 + 混沌钥石（新无尽）

**[设定]**

- **混沌仪**：**无尽挂机专属「建筑」**（同时承载原秘境的角色）。
- **解锁**：**通关全部野外地图 BOSS**。
- **T 阶**：`T1 ~ T16`；**开图 UI 只显示 T 阶**，怪物等级让玩家自己算。
- **生成规则**同 R2（普通 = 地图等级 / 稀有 +1 / BOSS +2）。
- **挂机机制（已定稿）**：玩家在混沌仪上**编排「钥石顺序」**，混沌仪**按该顺序逐个挑战**
  （投入一把钥石 → 打对应的 T 阶 → 结算 → 取下一把），全程**挂机自动推进**。
- **挑战失败选项（玩家可设，已定稿）**：
  - **(a) 回普通地图挂机**：中断钥石序列，角色回到普通野外图继续挂机；
  - **(b) 继续挑战**：不中断，按序列继续（同一把钥石可重试或跳到下一把 —— 见 §2.3 的默认）。
- **混沌钥石**：
  - **16 种**（T1 ~ T16 各一种），是**物品**；
  - 只在 **85+ 区域**掉落；
  - 怪物**最多掉比自己高 1 阶**的钥石；
  - **允许加工**：最多 **前缀 + 后缀共 4 条词缀** ⇒ **走背包，不进钱包**。

**[现状对照]**
- 现有秘境/无尽：`isDungeon` / `phases` / `group` / `isEndless` / `dungeonTickets` /
  `challengeQueue` / `cooldowns` / `resetPrice` / `nightmare.*`（31 张）。
- 09 任务书的 **R3（票/冷却/队列）与 R5（离线秘境编排）** 是为旧模型设计的。
- ✅ **已拍板：存量「氪金秘境」体系（神力买钥匙、每日 4 点冷却重置、挑战队列、双扣票、
  run 相位落库）直接弃用**，不做改造、不保留兼容。已交付的 R3-b1/R3-b2/R4/R5 相关代码
  与落库结构在 **W6** 一并删除；`dungeon` 段（140）随之退役或重定义为「混沌仪」。

**[坑]**
1. **钥石是"带词缀的装备类物品"**：它必须复用 `InventorySlot` + `AffixInfo` + 前后缀分池
   （正好吃上 `12` 的 E3 骨架）。因此钥石与通货/精华的承载**相反** —— 一个进背包、一个进钱包。
2. **钥石的"阶"如何与物品等级/词缀数值挂钩**：T1..T16 是 16 个 `GoodData`？还是 1 个底材 + 阶字段？
   建议 **16 个独立 key**（`keystone.t01..t16`），便于掉落表与展示。
3. **钥石加工**需要炼器系统（12 的 P9 / 上期遗留 A1）—— 两者**强耦合**，建议同期或先后紧接。
4. **旧秘境代码/落库整体删除**：涉及 `dungeon` 段（140）的 8 个 subCmd、`dungeon-queue-smoke`、
   `nightmare.*` 31 张图、`endlessLevel`、`AccountExtras.challengeQueue/dungeonRuns/dungeonCooldowns`。
   `logic-server-boundary` 的 `dungeon → map` 过渡白名单也要随之清掉。
5. **"钥石序列"是一种新的挂机编排**：需要新的状态（序列 + 失败选项 + 当前进度）与落库分区，
   并接入 tick / 离线结算（离线也必须能按序列推进，且**预算耗尽时停在当前钥石**）。
6. **"通关全部野外 BOSS"** 的判据：9 张单图 + 85+ 多图，是否要求 85+ 的每张图 BOSS 也杀？
   （默认：**要求全部**，含 85+ 多图。）

### 2.3 无尽机制的默认细则（Q5/Q6 已答，以下为实现默认，你可否决）

1. **钥石序列语义**：混沌仪按玩家编排的顺序**逐个消耗钥石**；每次消耗 1 把、打对应 T 阶。
2. **失败选项 (b)「继续挑战」的默认读法**：**重试当前这把钥石**（同阶重打），
   连续失败 **N=3** 次后自动跳到序列下一把（避免卡死；N 可调）。
   若你要的是"直接跳过当前、打下一把"，说一声，我改成那个语义。
3. **序列上限**：默认 **16** 条（= T 阶数），可重复放同阶钥石。
4. **离线也按序列推进**；预算耗尽时**停在当前钥石**，不做速率外推（沿用 09 RD7）。
5. **钥石来源**：本期**只做 85+ 掉落**（含怪物最多高 1 阶）；商店/分解等其它来源下期。
