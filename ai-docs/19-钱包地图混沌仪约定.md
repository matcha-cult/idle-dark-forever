## 19. 钱包 · 新地图 · 混沌仪（13 号任务书 W0–W7 重构后的硬约定）

> 来源：[`ai-docs/13-下一期重构-地图·无尽·钱包交接任务书.md`](ai-docs/13-下一期重构-地图·无尽·钱包交接任务书.md)。
> **本节覆盖 §18.6 与更早文档里关于「剧情 / 氪金秘境 / 旧地图」的旧描述**——那些系统已物理删除。

### 19.1 钱包（R1）：通货 / 精华不占背包格

- `GoodData.wallet?: boolean` 标记钱包物品。已标记：`currency.*`（12 种）+ `essence.*`（实装 6 + 空位 6）。
  **普通材料仍占背包**；**混沌钥石不是钱包物品**（走背包）。
- `Player.wallet: Map<string, number>`：**无容量上限**。`Player.loot` 命中钱包物品时走独立分支 ——
  不碰 `inventory`、返回**全额**（因此钱包物品永远不会 `handled:'lost'`）。
  `walletCount` / `costWallet`（原子扣款；0/负数/NaN/Infinity 均安全）。
- `PlayerJson.wallet` 落 `characters.state`；`fromJSON` 丢弃 ≤0 / 非有限值。
- DTO：`InventorySlotDto.wallet?`（服务端按 `good.wallet` 打标，`(battle,loot)` 推送复用同一 DTO）、
  `WalletEntryDto`、`PlayerStateDto.wallet?`（`walletDtoOf` 排序：goodOrder → key）。**前端零推导**。
- 钱包物品**本期不可卖店**（`opSell` 仍只作用于背包格）。

### 19.2 新地图（R2）：等级段 + 一次性野外 BOSS

- 地图种子在 `packages/game-core/src/data/maps-world.ts`（旧 `data/maps.ts` 已物理删除）。
  `home`（自宅）保留；战斗图为 `world.1`…`world.13`（**9 段各 1 张**，等级 = 段下界
  `1/5/15/25/35/45/55/65/75`；**85+ 共 4 张**，等级 85）。段首取 **1 级**（角色初始即 1 级）。
- 解锁（**W11 改口径**）：**只用 `bossKilled?: string`**（上一段守关 BOSS 所在图 key）——
  `world.1` **没有进入条件**，`world.2..9` 接 `world.(N-1)`，`world.10..13` 都接 `world.9`；
  `checkRequirement` 中 `bossKilled` 缺失即 fail-closed。
  ⚠️ **`level` 已从解锁条件里摘掉**（`stories`/`beforeStories` 更早已删除）：`MapEntry.level` 同时是
  怪物等级覆写来源，一旦它又是门槛，解锁线就正好落在经验衰减零点上 —— 历史上因此整条推进链
  不可达（`world.2` 实测 13→14 需 21228 次击杀）。`level` 现只作**内容/建议等级**，
  UI 展示、**不阻断进入**。回归：`game-core/src/data/maps-world.test.ts`
  （断言 `requirement` 恒为 `undefined` 或 `{ bossKilled }`）。
- **锁定原因（W11 / R4）**：`MapDto.lockedReason` **区分缺失条件**（`shared/map-dto.ts` 的
  `lockedReasonOf`）：「需先击杀「迷雾林间」的守关 BOSS」/「需要等级 15（当前 14）」；
  多条件用「；」串起来，`$and` 递归、`$or` 列「需满足其一」，分析不出来才回落通用文案。
  ⚠️ 它**只做展示**，绝不参与放行判定（判定唯一入口仍是 `checkRequirement`，fail-closed）。
  回归：`server/test/map-unlock-reason.test.ts`。
- **波次**（`combat/spawner.ts`）：1 波 = 该图 `monsters` 全部条目刷满 `config.total` 且清空；
  `Born.reset()` 单调推进，`EnemyBorn.wave` 随 `dumpState` 往返（离线/读档不丢波数）。
  新地图统一 **`total = 4`（每波 4 只）、`max = 4`（同屏上限 4 只）**。
- **同屏上限口径（W12）**：`Born` 的自然刷新闸门是 **`Born.aliveMonsterCount()`（全图存活敌对怪总数，
  含守关 BOSS 与 BOSS 召唤物；`camp` = `enemy`/`neutral`）**，**不是** `this.count`。
  达到 `max` 即暂停自然刷新，但**保持定时轮询**，有怪死亡后自动恢复（绝不永久停刷）。
  **BOSS 召唤物可以把总数推过 4**（设计允许）；玩家/联军召唤物（`player`/`alien`）**不计入**，
  否则玩家召唤会把刷怪卡死。波次完成判据仍只看 `total`/`count`（召唤物不参与计数）。
- **波次下发 + 持久化**：`WorldTickDto` / `WorldSnapshotDto` 带可选 `wave` / `bossEvery`
  （`WorldService.emitTick` / `snapshotOf`；`mergeWorldTick` 取**最新**帧，不得回退波数），
  前端 `world-store` 暴露 `wave` / `bossEvery` / `wavesToBoss` / `bossWave` 并显示在 `BattlePanel`。
  波数是**世界侧车状态**：落在 `AccountExtras.worldMaps[characterId].wave`（**不进** `characters.state`），
  `WorldService.start()` 恢复、`persistPosition()` 写回、切图 / 重复进图（重置本图）自然归 0；
  脏值（NaN / 负数 / 非数字）一律按 0 处理（`worldWaveOf`）。
  ⚠️ `unitStateDtoOf` 在 `server/.../world/internal/unit-state.ts`（**不在** `shared/`）。
- **守关 BOSS**：每 `WORLD_BOSS_WAVE_INTERVAL = 20` 波尝试刷新；同屏一只；
  **一次性**——击杀记在角色 `Player.worldBossKilled: Set<string>`（`PlayerJson.worldBossKilled`），
  已击杀的图不再刷 BOSS 但普通怪照常 farm。BOSS 单位用显式 `worldBoss` 标记（**不要用 key 比较**：
  `slime.queen` 既可能是某图 BOSS 又是另一图普通怪）。
- **`bossPending`（「BOSS 还会不会出」）是唯一判据**（W4 后续修正）：
  `BattleWorld.bossPending` = 地图有 `boss` 且 key 在敌人表里，并且（混沌图 ∨ 尚未击杀）。
  它同时被**两处**读取，因此不存在第二份判定：
  ① 刷怪闸门 `EnemyBorn.trySpawnWorldBoss`（`if (!this.world.bossPending) return;`）；
  ② UI 的「距守关 BOSS N 波 / 守关 BOSS 现身」。
  - 下发：`WorldTickDto.bossPending?` / `WorldSnapshotDto.bossPending?`（可选字段）；
    翻转本身算一次变化（`worldFrameOf` 的 `hasContent` 含它），`mergeWorldTick` **取最新帧**
    （击杀后不得被同批旧帧翻回 `true`）。
  - 前端：`world.bossPending === false` ⇒ **整条 BOSS 文案都不渲染**（含「现身」）。
  - ⚠️ **不要**再按 `wave % bossEvery` 直接显示倒计时：野外图通关后那个倒计时永远不会到来，
    这正是用户报的「波次 2 距守关 BOSS 18 波」在已通关地图上的错误显示。
  - 前端缺省 `false`（服务端未下发时**宁可少显示**，也不显示错误倒计时）。
- **怪物等级**（`EnemyUnit.levelOverride`，`BattleWorld.addEnemy` 对非混沌图设置）：
  **`mapLevel + min(quality, 2)`** —— 普通（`quality 0`）+0 / 稀有（1）+1 / 精英（2）+2；
  守关 BOSS 由 `trySpawnWorldBoss` 覆写为 +2。地图无 `level` 时回落旧公式。
  ⚠️ W11 之前是 `quality >= 1 ? +1 : 0`（三阶口径），四阶后按档位逐级 +1；
  `clampEnemyQuality` 同时兜住 `quality` 脏值（`Infinity` 曾让等级/词缀爆炸）。
- **经验不做等级差衰减**（W10 已移除）：`PlayerUnit.gotExp` 曾按
  `dis = min(自身等级, 70) − 怪物等级` 每级递减 10%、`dis ≥ 10` 时**归零**（`EnemyUnit.kill` →
  `world.gotExp(this.exp, this.level)`）。那道窗口恰好等于段位宽度（解锁门槛 = 上一段内容等级 + 10），
  于是**越接近解锁线经验越低、到线归零** → 整条推进链事实上不可达：
  `world.2`（地图等级 5）实测 13→14 需 **21228 次击杀 ≈ 5300 波**，全库 388 角色无一自然推进过 `world.2`。
  现平衡由**怪物经验分布**（`enemyData.exp` × `2 ** quality`）+ 角色经验倍率 `expRate` 承担。
  ⚠️ **后期调整经验曲线不要再引入等级差系数**。`gotExp` 的第二个参数（怪物等级）保留为
  冻结端口契约的一部分，但**当前不参与任何计算**（传 0 / 负数 / NaN / Infinity / 极大值结果相同）。
  `transformEquipLevel` 只用于装备等级口径（如 `stunResist`），不要用在经验判定。
  回归：`game-core/src/combat/exp-no-level-penalty.test.ts`。
  沿革：`a39d2a5`（改真实等级）→ W10 整体移除该窗口。
- **刷怪池必须按真实数值 + 阵营挑选**（不能只看 `level` 字段）：普通怪与守关 BOSS 必须是
  `camp:'enemy'` 且非 `onPress` 机关 —— `neutral` 不会被自动索敌（挂机卡波次）、
  `alien`（如 `chapter3.fishzilla.magician`）**玩家根本无法攻击**；且 BOSS 的 HP 不得低于本图普通怪。
  `data/spawn-eligibility.test.ts` 是门禁。
- 等级上限 **100**（`CareerInfo.maxLevel` 默认 100，`CareerData.maxLevel?` 可覆写）；
  **巅峰等级体系已全部删除**（`peakLevel`/`peakExp`/`maxPeakExp`/`levelUpPeak`、DB `peak_level`）。
  满级后经验溢出直接丢弃，不再有任何巅峰轨迹。

### 19.3 混沌钥石（R3 / W5）：PoE 式白图

- 16 种独立物品 `keystone.t01`…`keystone.t16`（`data/goods.ts`）：`type:'material'` + `stack:9999`，
  **本期无词缀、无加工入口、不接 `AffixInfo`**；同阶可堆叠；**不进钱包**。
- 掉落规则（`rules/keystone.ts` + `BattleWorld.rollKeystoneDrop`）：
  `tier = clamp(floor(level) - 84, 1, 16)`；**仅地图 `level >= 85`** 掉落；
  单只怪最多掉 **自身阶 + 1**（`maxKeystoneDropTier`）；基础率 `KEYSTONE_DROP_RATE`，
  掷阶 `P(cap)=0.75` 否则在 `1..cap-1` 均匀。全程走 `rng.loot`，**禁止 `Math.random()`**。
- 词缀化 + 洗图参考 PoE，随 A1 炼器一起做（届时改为按实例、不堆叠）；T16 后的「梦魇地图」属后续。

### 19.4 混沌仪（R3 / W6）：无尽挂机建筑

- 地图种子 `data/maps-chaos.ts`：`chaos.t01`…`chaos.t16`，**地图等级 = 84 + T**（`MapData.chaos?: number`）。
  **开图 UI 只显示 T 阶**；混沌图从 `map.list`（`mapListDtoOf`）中过滤，普通 `map.enter` 一律 `MAP_LOCKED`。
- **解锁 = 通关全部野外 BOSS**（13 张 `world.*`），判定 `Player.hasAllWorldBossesKilled()`。
- **钥石序列**：`Player.chaosSequence: string[]`（≤16，可重复）、`chaosFailMode:'normal'|'continue'`、
  `chaosIndex` / `chaosRetry` / `chaosActive`，随角色存档往返。
- 状态机唯一实现在 `packages/server/src/modules/logic/chaos/internal/chaos-ops.ts`（纯函数，在线/离线共用）：
  每次进入消耗 1 把钥石；`clear` → 下一把；`death + normal` → 中断回普通地图；
  `death + continue` → 重试当前把，**连败 3 次跳下一把**；越界 / 缺钥石 → 干净停止。
- 运行接线：battle 的 `BattleWorld.chaosOutcome`（混沌 BOSS 死 = `clear`，**不写** `worldBossKilled`、可重复刷；
  玩家死 = `death`）→ `WorldService.tick` 发跨服事件 **`ChaosRunEnded`**（`shared/events.ts`）→
  `ChaosLogicService` 订阅后用 `BATTLE_COMMAND.enterMap(..., { allowChaos: true })` 推进。
  ⚠️ `clear` 必须等守关 BOSS **清尸（`clean()` 掉落结算）后**才上报，否则换图会 dispose 掉清尸计时器、吞掉落。
- 协议：`CMD_SEGMENTS.chaos = 140`（**复用已退役的 dungeon 段**）、`CHAOS_CMD{state,setSequence,setFailMode,start,stop}`；
  逻辑服 `idle` 同时拥有 `idle(120)` 与 `chaos(140)`（roots 含 `modules/logic/idle` + `modules/logic/chaos`）。
- **离线**：`IdleService.settle` 在 `chaosActive` 且持久化地图是混沌图时，用同一 `VirtualClock`/预算循环模拟并复用
  `chaos-ops` 推进；**预算耗尽 / run 未结算 → 停在当前钥石，`extrapolatedMs = 0`**（混沌部分不外推）。
  非混沌图的开放世界 C2 外推保持不变。
- 前端面板 `ChaosPanel.tsx` + `chaos-store.ts`（T1~T16 + 钥石数、可编辑序列、失败选项、start/stop）。

### 19.7 W11 波次里程碑：精英 / 通关清算 / 阵亡重开 / 世界侧车

> 产品来源：用户提案「通关前 10 波精英 + 20 波守关 BOSS；通关后转每 10 波精英；任意波次死亡自动重开本图」。

#### 节拍（三态）

| 图 | 精英 | 守关 BOSS |
|---|---|---|
| 野外 · **开荒**（`bossPending === true`） | 第 **10** 波，一次 | 第 **20** 波，一次 |
| 野外 · **挂机**（已通关） | 每 **10** 波 | **不再出** |
| **混沌图** | **不出** | 每 **20** 波，可重复刷 |

- 唯一实现：`combat/spawner.ts` 的 `eliteWaveTarget()` / `bossWaveTarget()` / `ensureMilestones()`；
  `completeWave()` 与会话恢复（`WorldService.start` → `buildBattleWorld` 之后）都调用。
- ⚠️ **闸门是「目标波 + 已交付记录」，不是 `wave % N === 0`**。取模在**会话恢复**后必然错过窗口：
  旧实现恢复到第 20 波时 `21 % 20 !== 0`，首次再出要等到第 40 波（R3，实测
  `ai-script/explore/check-boss-respawn.mjs`）。
  - **野外 BOSS**：判据是「`bossPending` 且场上没有 BOSS」⇒ **丢失（刷新/重连）后当波补刷**；
    ⚠️ **不要**再叠一层 `lastBossWave !== target`，那会把 R3 从「等到第 40 波」变成「永远不出」。
  - **混沌 BOSS**：按 20 波窗口记 `lastBossWave`，否则杀掉后每一波都会重刷。
  - **精英**：按 `lastEliteWave` 记窗口 + 「场上无存活精英」双闸门（同一时刻只允许一只）。
- I2 超载：`spawnElite` / `trySpawnWorldBoss` 都先查 `world.atUnitCap()`；**交付失败不记里程碑**，
  下一波自动重试（不永久丢失）。

#### 精英（决策 3）

- = **强制 `quality = 2`** 的普通怪（`ELITE_QUALITY`）：两条词缀 ⇒ `maxHp` / `exp` ×4，
  `displayName` 会拼出词缀前缀，等级 `mapLevel + 2`，稀有度第 2 档。
- **必掉**：`BattleWorld.lootEliteGuaranteed(loots, level, quality)` 在该怪清尸时额外结算一条
  通货/精华 —— 从**该怪自己的 `loots`** 里筛出 `tables.goods[key].wallet === true` 的 `key` 条目，
  按各自 `rate` 作权重抽一条，强制 `rate = 1`（⇒ `count = ceil(1 − rng) = 1`）。
  - 为什么不靠 `quality` 自动化：`loots(…, quality)` 的 `quality` **只**作用于
    `entry.type === 'equip'` 分支，而怪物掉落里的 equip 类**已物理删除**（W7）—— 品质对掉落零影响。
  - 为什么是"真保证"：钱包物品不占格、无上限、永不 `handled:'lost'`，且 `key` 类条目在
    `loots()` 里直接 `handled:'pickup'`（**不经过拾取规则**）。刻意的：绕过玩家设置会让
    「自动出售/分解」静默失效（AGENTS §11 的教训）。

#### 稀有度四阶（决策 3 的展示面）

- `普通 / 稀有 / 精英 / 传奇` = `quality 0/1/2` + 守关 BOSS。唯一实现
  `game-core/src/combat/enemy-rarity.ts`：`enemyRarityOf({ worldBoss, elite, quality })`
  优先级 `boss(3) > elite(2) > clampEnemyQuality(quality)`；另有 `normalizeEnemyQuality`
  做**字段级**安全化（`Infinity` / `NaN` / 负数 / 超大值 → 0 / 夹到 `MAX_ENEMY_QUALITY = 8`）。
  ⚠️ `quality 2` 归**精英**而不是稀有 —— 归错就等于退回三阶。
- 协议：`UnitStateDto` 追加可选 `elite?: boolean`（出生标记）与 `rarity?: number`
  （**服务端派生**，前端零推导，与 `alive` 同一先例）；`UNIT_RARITY_NAMES` 是文案唯一真相。
- 前端：**唯一渲染处是 ui-kit 的 `UnitCard`**（用 `UnitRarityTag`；文案表 `UNIT_RARITY_LABELS`
  与协议逐字比对，色板由应用层 `RarityPaletteProvider` 注入，精英用 `token.purple`）。
  **HUD 不显示精英倒计时**（产品拍板拍板：不显示精英怪物刷新时机）。
  ⚠️ **一只单位只允许一个档位徽标**。`UnitCard` 原先渲染 `<RarityTag quality={unit.quality} />` ——
  把**词缀条数**当装备品质，于是一只 `quality 2` 的精英怪被画成**传奇**、与真 BOSS 撞色，
  同一只怪身上同时出现「传奇 + 精英」（用户截图报的正是这个）；同时 `BattlePanel` 的 `extra`
  槽又贴了一遍 `UnitRarityTag`，于是普通稀有怪出现**两个「稀有」**。现已：
  ① 删掉 `UnitCard` 里那条装备品质标签（`rarity` 缺省时不贴标，不退回 `quality` 那条轴）；
  ② 删掉 `BattlePanel` 里的档位标签（`UnitCard` 内部已渲染）；
  ③ 删掉「守关 BOSS」独立标签（它的档位就是传奇，同义重复）。
  单位卡现在最多两个标签：**一个档位徽标 + （中立 / 被锁定）**。
  回归：`ui-kit/src/game/unit-card.test.tsx`（含「一只单位最多一个档位徽标」）。

#### 通关清算（决策 2）

- 击杀本图守关 BOSS **首次**时一次性发放 `MapEntry.exp`（`BattleWorld.grantWorldClearReward`），
  走 `world.gotExp(exp, playerUnit.level)` —— 原版秘境 `DungeonState` 的清算口径；
  此前 `MapEntry.exp` 是**死字段**（全仓唯一引用是一条 `Number.isFinite` 断言）。
- ⚠️ **必须先读 `hasWorldBossKilled` 再 `markWorldBossKilled`**，否则重连/补刷路径会重复发奖。
- `expRate` / `expInc` / `expMul` 照常生效；`exp` 缺失 / 非有限 / `<= 0` → 一条事件都不发。
- 混沌图**不发**（可重复刷，不属于 `worldBossKilled` 链）。`world.1..13` 统一规则，无按段特例。

#### 阵亡重开（决策 4）

- 任意波次阵亡 → 本图 run 重开：`wave = 0`、里程碑复位、清场、重新武装刷怪器。
- ⚠️ **不加任何护栏**（产品原话：*"连续死肯定是玩家问题……系统不为玩家做选择"*）：
  不做「连续死亡 N 次停手」、不自动退回上一张图、不弹确认。
- 实现：`PlayerUnit.kill()` 只置位 `BattleWorld.openWorldDeath`（**非混沌且 `isCombatArea`**），
  由 `WorldService.tick` 在 `emitTick` **之前**调 `resetOpenWorldRun()`（复用「重复进图 = 重置本图」
  的 `onMapChanged()` 路径），因此清场 + 「进入地图」日志与同一帧一起下发。
  **有意不销毁 / 不重建会话**（那会牵进离线锚点 `player.timestamp`、`opId` 幂等、跨服命令与会话回收竞态）。
- 复位后立刻 `persistPosition()`：否则紧接着的刷新会读回旧波数。

#### 世界侧车（R0，C6 单一写者）

- 形状：`account_state.data.worldMaps[charId] = { map, wave?, lastEliteWave?, lastBossWave? }`
  （JSONB，**不需要 Prisma 迁移**）。读写唯一入口：
  `shared/world-map-state.ts` 的 `parseWorldMapState` / `writeWorldMapState` /
  `writeWorldMapKeepingProgress` / `cloneWorldMaps` / `worldWaveOf`。
- ⚠️ **为什么必须收口**：`WorldService.persistPosition()` 写 `{ map, wave }`，
  而 `IdleLogicService.settle()` 只写 `{ map }` —— **把 `wave` 抹掉**。后者在**每次登录**都会跑
  （`root-store` 拉离线报告），于是「波数」永远不可能跨会话。这是**同一片状态两个写者且形状不一致**，
  正是 C6 禁止的情形。
- 离线结算**不推演波次**：只保留进度；并把已交付里程碑（仅当侧车记录的就是该图时）喂给离线模拟，
  避免重复交付精英 / BOSS。换图 → 进度归零（`writeWorldMapKeepingProgress` 比对 map）。
- `parseWorldMapState` 的脏数据防御：非对象 / 数组 → 跳过；`map` 非法 → `home`；
  波数类字段非正 → 省略；**里程碑晚于 `wave` → 丢弃**（否则会"提前认为已交付"而永久漏刷）。

### 19.8 W12：守关 BOSS 在场则停刷杂兵 + 通关自动重进本图

> 产品来源：用户提案「**当守关 boss 刷新或者存活的时候，不再刷新新的怪物**」，
> 并在同一轮追问中确认「击杀守关 boss 之后自动重新进入当前图重开波次」这条（W11 决策 3 的
> 另一半）当时**尚未实现**。

#### ① 闸门：BOSS 在场 ⇒ 一只杂兵都不刷

- 落点唯一：`Born.onTimer`（`combat/spawner.ts`），在原有两个闸门**之前**：
  `hasWorldBossUnit()` → `atMonsterCap()` → `world.atUnitCap()`。
- 三条闸门**语义一致**：都是「**保持轮询**」（`setTimer()` 重新武装）而不是永久停刷 ——
  条件一消失（BOSS 离场 / 有怪死 / 掉到硬顶以下）就自动恢复，**不需要任何人重置状态**。
- 判据 `BattleWorld.hasWorldBossUnit()`：**存在**（含已死未清尸的 `ghost`），**不是存活**。
  与混沌 `clear` 等掉落用的是同一个判定，但**消费意图不同**：
  | 消费方 | 意图 |
  |---|---|
  | `WorldService.publishChaosOutcome` | 等 BOSS **清尸**（掉落 / 钥石在 `clean()`），否则换图吞掉落 |
  | `Born.onTimer`（本闸门） | BOSS 在场就**不刷杂兵**（产品拍板，尸体也算在场） |
  | `WorldService.handleRunReset` | 通关重开前**等清尸**（同上，掉落必须落地） |
- **副作用（产品已接受）**：BOSS 波期间 `Born.total` 恒达不到 `config.total(4)` ⇒
  `isWaveComplete()` 不成立 ⇒ **波数冻在 BOSS 那一波**。这正是「BOSS 波只有 BOSS」的代价。
- ⚠️ **已知尾巴（world.11）**：BOSS `chapter3.beast.pengpeng` 携带 `simba.goodFriends`，
  其 `willClean` 在「仍有兄弟存活」时返回 `false` ⇒ **尸体不挂清尸计时器**；而该图刷怪池里就有
  同为携带者的 `chapter3.beast.dingman`。⇒ 「BOSS 死时还有兄弟活着」会让尸体一直留在场上，
  杂兵停刷直到**最后一个兄弟死亡**时统一 `setCleanTimer()`。**不是永久锁死**，但要求清完残兵。
- ⚠️ **只拦守关 BOSS**：
  - **精英**（`elite`，每 10 波保底）不拦 —— 它是 `borner = null` 的普通怪，不触发闸门；
  - **敌方召唤物**不拦 —— 走 `data/skills.ts` 的 `addEnemy(..., summoner)`，不经刷怪闸门。
    拦它等于废掉 world.4/6/8 三只 BOSS 的看家技能（`wolf.call` / `candle.call` /
    `necromancer.ghostShield`，实测确认）。

#### ② 通关 ⇒ 自动重进本图（补全 W11 决策 3）

- 内核：`EnemyUnit.kill` 的非混沌分支在登记通关后调 `world.noteWorldCleared()`
  （混沌图**不置位** —— 那边走 `chaosOutcome`，由混沌域决定后续）。
- 服务端：`WorldService.handleRunReset`（两个触发源共用一个消费者）
  在 `openWorldCleared && !hasWorldBossUnit()` 时 `resetOpenWorldRun()`。
  - **必须等清尸**：掉落 / 钥石在 `clean()` 结算，提前重开会 `dispose()` 清尸计时器 → **吞掉落**；
  - 重开后 `player.worldBossKilled` 已登记 ⇒ `bossPending === false` ⇒ **自动转挂机节拍**；
  - 通关清算经验在 `kill()` 里已发到玩家（不在世界里），因此重开**不会吞掉它**；
  - 时序：**BOSS 死 → 登记 + 发清算经验 → ~3s 等清尸（掉落落地）→ 重进本图 + 波次归 0**。
- ⚠️ **与阵亡重开（决策 4）方向相反**：阵亡**不等清尸**（阵亡时 BOSS 通常还活着，等它就是永不重开）。
  两个标志同时置位时**阵亡优先**。
- 离线：`applyRunResets`（`idle-logic.service.ts`，导出以便单测）实现同一语义，
  在每个快进分片后调用。**不做的话**「带着一个打不死的 BOSS 下线」会因停刷杂兵导致
  模拟区间击杀≈0 ⇒ `extrapolate` 乘 0 速率 ⇒ **整段离线收益≈0**。
